## Before updating

- This is a fairly hefty overhaul of the whole thing, but it is mostly backwards compatible barring the notes below.
- It's now `@garethnunns/content-tracker`, so run it with `npx @garethnunns/content-tracker`. The old package won't be updated.
- The top folder is now tracked as `/` rather than with an empty path, so its record is removed and added again on the first run - any other fields on that row will be deleted too.
- Images that were wrongly marked as having alpha, like greyscale ones, are corrected, so they update on the first run.
- The metadata cache has moved to your user cache folder, so the first run looks at every file again. The old `.db` folder can be deleted.
- In `settings.airtable`, `api` is now `token`, and `foldersID` and `filesID` are now `foldersTable` and `filesTable`. A config with the old names says what to change.
- Rules are matched against the path as it's tracked, like `/05 Delivery/a.tif`, rather than the whole path on your computer, so a rule that includes where the folders are, like `/Volumes/Show`, needs that taking out. Dry run to check what they match.
- A setting it doesn't know, like a typo, now stops it running and says which, rather than being ignored.
- `concurrency` now limits the whole scan rather than each folder, so the same number is a lighter load - you may want to raise it.

## New

- An app for Mac (Apple Silicon and Intel) and Windows, to set it up, try a dry run and keep your tracker up to date without the command line.
- The app lives in the menu bar, where you can see what it's doing, run it once, start watching or open it at login, and it carries on watching when it's next opened.
- The app has Help, to get started, and About, with what it's built with.
- The app updates itself: when there's a newer version, **Update and restart** downloads and installs it.
- The command line says when there's a newer version, and how to get it.
- Google Sheets, as well as Airtable.
- Sign in with Google or Airtable, in the app or with `tracker login`, rather than making a token or service account.
- Choose an Airtable base from a list, and give a spreadsheet by its link.
- Removing the records of deleted files, and warning before removing more than 10%, can each be turned off in the config (`removing`) or the app's settings, rather than only with `-nd` and `-nc`.
- Track just the files, without a folders table (`trackFolders`).
- `_sizeText`, the size as the Finder shows it, like 1.84 GB, beside `_size` in bytes.
- **Tracked** in the app lists what was found, with its size, dates and media details, sorted however you like, including by when it was first found. After a dry run it's coloured by what would change, and clicking something excludes it by its name, folder or extension.
- The app's settings save as you change them, and can be exported as a config file as well as imported.
- Sheets it creates warn whoever goes to edit the tracker's columns by hand, and show true and false as tick boxes.
- Clear the media metadata cache from the app's settings.
- The tables, sheets and fields it needs are created the first time it runs, with a note on each saying not to change the `_` fields.
- The Airtable token can come from `AIRTABLE_API_KEY` and the Google key from `GOOGLE_APPLICATION_CREDENTIALS`, so neither has to be in the config.
- It can be run as `content-tracker` as well as `tracker`.
- A config only needs its folders and where they're tracked: everything else has a default, and the Mac's `.DS_Store` files aren't tracked.
- Rules can be globs, like `*.mov` or `**/05 Delivery/**`, as well as regular expressions, and a `/` in a regular expression no longer needs escaping.
- Editors like VS Code suggest and explain each setting as you write a config.

## Improved

- A folder that can't be read, like an unmounted drive, no longer looks as though everything in it was deleted: nothing is removed that run.
- New folders are linked to their parent in the same run, rather than the next.
- Media metadata is only read again when a file changes, rather than every run.
- Rules written with `/` work on Windows paths too.
- A config with mistakes lists all of them at once.
- It exits with an error when something goes wrong, for cron jobs, and with no one there to ask, it leaves a big removal for next time rather than waiting a minute for an answer.
- Running it without a config never overwrites an existing `config.json`, and the one it makes can only be read by you.
- `view` can be left empty to compare against the whole table.

## Fixed

- Greyscale images, and others without alpha, were marked as having it.
- Shortcuts that led back to a folder above them made the scan go on forever.
- A folder listed twice, or inside another listed folder, was tracked twice.
- Errors from Airtable could go unreported.
